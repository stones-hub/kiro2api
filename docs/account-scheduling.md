# 多账号调度规则

只适用于管理模式（`KIRO_ADMIN_DATA_DIR`）。旧版 `KIRO_AUTH_TOKEN` 直连模式不在本次范围内。

## 目标（用户确认）

1. 会话有粘性：续接的对话回到上一轮的账号；只有该账号异常时才换。
2. 新会话分到剩余空位（并发上限 − 当前并发）最多的账号；并列时随机选一个。
3. 调用出错时，服务端自动换到当前剩余空位最多的另一个账号重试 1 次。

## 规则

### 1. 粘性

- 粘性始终开启，不再依赖 `KIRO_LOCAL_CACHE_DISCOUNT`。该开关只决定是否向客户端报告本地缓存折扣（`cache_read_input_tokens` 和 `X-Kiro-Cache-Accounting` 头）；关闭时 usage 输出与现在完全一致。
- 会话识别沿用现有方式：API Key + `metadata.user_id` + 模型 + 消息前缀哈希，记录保留 5 分钟（与 Kiro prompt cache 失效时间一致）。
- 账号"异常"指：停用、删除、凭据错误、额度用完、冷却中（402/429/401/403/代理故障/月度次数用完）、token 过期。异常时立即换号。
- 账号正常但并发满：最多等 `KIRO_STICKY_WAIT_SECONDS`（默认 10 秒），期间空出的槽位留给它；等不到再按新会话分配（保持现状）。

### 2. 新会话分配

- 若管理页设置了套餐优先级（PlanOrder），先按优先级分组。
- 同组内按剩余空位从多到少；剩余空位相同的账号之间随机。

### 3. 出错换号重试

- 只在上游还没给客户端返回任何内容时重试（发出请求到收到 200 之前）。流式输出中途断开不重试。
- 触发重试：上游 401、402、403、429、5xx，网络错误，账号代理故障。
- 不重试：400、413 等请求本身的问题；客户端已取消。
- 流程：按失败结果释放当前账号（401/402/403/429/代理故障照旧进入冷却）→ 排除该账号，按规则 2 选新账号 → 用新账号的 token 重建请求再发一次。
- 最多重试 1 次。第二次仍失败，返回第二次的错误。
- 重试成功后，会话记录改到新账号，下一轮直接粘在新账号上。
- 管理页统计：失败那次记在原账号，重试那次记在新账号。
- 覆盖 `/v1/messages`（流式/非流式）和 `/v1/chat/completions`（流式/非流式）。WebSearch 路径不在本次范围内。

## 验证

- 单元测试：粘性在折扣关闭时生效；折扣关闭时 usage 不含本地缓存字段；并列账号随机分布；重试排除失败账号并选空位最多的账号；400 不重试；重试最多 1 次；重试成功后会话记到新账号。
- 本机验收：用模拟上游起两个以上账号，验证同一会话连续请求落在同一账号；让其中一个账号返回 429/500，请求自动落到另一账号且客户端拿到 200。
